# 量化操作指南（WebUI）

这份文档讲**如何在 WebUI 里完成一次模型量化**：从填模型、选格式与校准数据集，
到启动、看日志、验证结果。前置条件：服务已在 GPU 机 7861 端口运行，浏览器能打开
`http://<gpu机ip>:7861`（部署与配置见根 README）。

## 整体流程

```text
模型量化区：模型 → 量化格式/recipe → 校准数据集 →（导出与资源 / 高级参数）
            → 核对命令预览 → 开始量化
任务面板：  实时日志 + 阶段进度，直到 done / failed
配方对照区：选这次任务 → 量化范围摘要 +（可选）官方模型卡对照 diff
模型仓库与导出区：导出产物清单
```

## 前置检查（一次性）

| 检查项 | 怎么看 | 没就绪怎么办 |
|---|---|---|
| 量化 venv | 系统设置与日志区 | 点「创建 venv」（5–15 分钟，日志尾部出现 `VENV_DONE` 即完成） |
| HF 网络 | 顶栏 / HuggingFace 网络面板 | 面板里设代理（`mode: manual` + `proxy`）并测连通性 |
| 本地模型 | 量化区模型卡 | 目录必须含 `config.json`；系统启动前会预检，目录不存在或不是模型目录会直接报错，不会浪费一次运行 |
| GPU 空闲 | 顶栏 GPU 徽标 | 显存占用 > 24G 时启动前弹「GPU 当前被占用」警告，不抢占正在用的卡；确认可跑才点继续 |

## 第 1 步：填模型（「模型」卡）

- **模型路径 / HF id**：两种写法——HF ID（如 `Qwen/Qwen2.5-1.5B-Instruct`，走
  HF 缓存）或本机路径（`~` 或 `/` 开头，以 WebUI 所在机器为准）。
  本机已有模型可直接点模型卡下方的快捷条目选择。
- **trust_remote_code**：模型带自定义代码（部分 GPTQ/合并仓库）时打开。
- 填入模型与格式后，页面「显存估算」面板会带入初值，供参考。

## 第 2 步：选量化格式（「量化」卡）

- **量化格式（qformat）**：默认 `nvfp4`。选项是运行时从仓库真扫出来的，
  ModelOpt 升级后新格式自动出现；扫不到时回落到内置快照并标注。
- **KV 量化**：默认 `none`；选了值才拼 `--kv_cache_qformat`。
- **recipe（可选）**：优先于 qformat。填了 recipe（路径或 ID）就不再拼
  qformat；留空 = 用默认 recipe。

> 三者不是叠加关系：**recipe 填了，qformat 不生效**。

## 第 3 步：选校准数据集（「校准数据集」卡）

- **内置数据集**：逐行勾选，每行有独立的 calib_size（校准样本条数）输入框，
  留空用默认 1024（`config.yaml` 的 `defaults.calib_size`）。
- **自定义数据集**：加行，填数据集名 + 条数（条数可留空，用默认值）。
- 命令按勾选顺序拼成 `--dataset 名1,名2 --calib_size n1,n2`。
- **至少勾选一个数据集**，否则「开始量化」按钮禁用。

## 第 4 步：导出与资源、高级参数（可选）

「导出与资源」卡：

- **export_path（可选）**：量化产物落盘目录。留空 = 默认目录「模型名_ptq」。
- **batch_size / device / gpu_max_mem_percentage**（0 = 不限制）。
- **calib_seq**（校准序列长度）、**calib_with_images**（图文校准开关）。

高级参数（折叠区）：`attn_implementation`、`use_fsdp2`、`cpu_offload`、
`low_memory_mode`、`skip_generate`——按需打开，不确定就保持默认。

**extra_args（逃生口）**：原样拼到命令尾，用于 UI 没暴露的参数。
禁止 `;` 与 `&&`（防止拼出第二条命令），违反会被拒绝。

## 第 5 步：核对命令预览

命令预览是**将要实际执行的命令**（切到仓库目录、用量化 venv 跑
`hf_ptq.py`），与最终执行逐字节一致，含 `--dataset` / `--calib_size` 拼接。
启动前重点核对：模型路径、格式/recipe、数据集与条数、导出目录。

若后端参数扫描（ModelOpt 版本 + `hf_ptq.py` 支持的 flag 列表）失败，
预览下方会标注「未做 flag 差集校验，请自行核对命令」——此时以仓库
实际支持的参数为准。

## 第 6 步：开始量化

点「开始量化」后**立即返回**，任务面板新增一个任务：

- 任务目录：`<task_dir>/<模型标识>_<时间戳>/`，完整日志在其中的 `run.log`。
  模型标识规则：本地路径取末段目录名，HF ID 用 `org__model`。
- 本地路径错误在这里之前就会被预检拦下：目录不存在 →「没有找到这个目录」；
  目录在但没有 `config.json` →「不像 HF 模型目录」。
- 参数含仓库不支持的 flag 时启动即被拒（unknown_flags），提示具体缺哪个参数。

## 第 7 步：跟踪任务

- 任务面板（模型量化区下方）：实时日志尾 + 阶段进度条；状态依次为
  `starting → running → done / failed / aborted`。
- **中止**按钮可随时发中止信号。
- 服务重启后，仍在运行的任务会自动恢复跟踪（进程还活着就继续看；
  进程没了按日志尾判定终态）。

## 第 8 步：验证结果（「配方对照」区）

任务 done 后：

1. 进「配方对照」区，选这次任务 → 系统扫描导出目录的量化配置
   （`config.json` / `hf_quant_config.json`），给出**量化范围摘要**：
   每组位数 × target 数 × 代表 target + ignore 列表 + 文件清单。
2. （可选）填**官方模型卡 ID** → 走代理拉官方 `quantization_config`，
   与本次产物做 diff，逐组标出一致 / 差异。
   官方对照失败不影响主产物，只展示失败原因。
3. 导出产物在「模型仓库与导出」区按目录列出。

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| 「没有找到这个目录」 | 本地路径在 WebUI 所在机器（GPU 机）上不存在——路径以 GPU 机为准，不是浏览器的机器 |
| 「没有 config.json，不像 HF 模型目录」 | 目录不是完整 HF 模型（缺 config.json）；换个目录或先把模型下全 |
| unknown_flags（本版本没有这些参数） | 仓库里的 `hf_ptq.py` 版本不支持该参数：升级 Model-Optimizer 仓库，或去掉对应高级参数 / extra_args |
| venv 未就绪 | 系统设置与日志区「创建 venv」，等 `VENV_DONE` |
| HF ID 模型拉取慢 / 失败 | HuggingFace 网络面板设代理并测连通；本地路径模型不受影响 |
| 「GPU 当前被占用」 | 有进程占显存 > 24G；等释放，或确认不冲突后继续 |
| extra_args 被拒 | 含 `;` 或 `&&`，改成单参数写法 |
| 任务目录名认不出 | 本地路径取末段目录名、HF ID 用 `org__model`，再拼时间戳 |

## 默认值速查

| 项 | 默认 | 说明 |
|---|---|---|
| qformat | `nvfp4` | `config.yaml` `defaults` |
| KV 量化 | `none` | 不拼 `--kv_cache_qformat` |
| calib_size | `1024` | 每数据集默认条数 |
| calib_seq | `512` | 校准序列长度 |
| device | `cuda` | |
| batch_size | `0` | 0 = 不指定，由脚本默认行为处理 |
| export_path | 留空 | 默认目录「模型名_ptq」 |
| gpu_max_mem_percentage | `0` | 0 = 不限制 |
| task_dir | `~/quant-webui-tasks` | 任务与日志根目录 |
